# 项目设计规范

本文件是 `chinese-classical-colors` 当前 UI 设计的项目级规范。  
后续对首页、色谱浏览、导出页、移动端弹层与预览模块的改动，都应优先遵循本规范，而不是局部单独定义视觉语言。

对应代码来源：

- 规范数据源：`lib/design-spec.ts`
- 指南页面实现：`components/color-workbench/guide-view.tsx`
- 全局视觉 token：`app/globals.css`

## 1. 设计目标

- 用现代精确网格承载古典意味，避免“古风元素堆砌”。
- 以宣纸底、白瓷面、墨色字与朱砂锚点建立主视觉秩序。
- 保持工具产品的可操作性、信息密度与东方气质之间的平衡。

## 2. 视觉原则

- 简：不使用大面积多色渐变，通过细墨线与留白建立层次。
- 远：主区块留白偏宽，页面纵向节奏应有呼吸感。
- 凝：高纯度朱砂红只用于关键动作、导航状态与落印位置。
- 润：动效以缓入缓出为主，避免闪烁、弹跳和高频干扰。

## 3. 色彩 Token

核心 token 以 `:root` CSS 变量为准：

```css
:root {
  --bg-paper: oklch(98% 0.005 85);
  --bg-surface: #ffffff;
  --fg-ink: oklch(18% 0.01 70);
  --fg-muted: oklch(45% 0.008 70);
  --border-ink: oklch(20% 0.01 70 / 8%);
  --border-ink-active: oklch(20% 0.01 70 / 24%);
  --accent-cinnabar: oklch(50% 0.18 30);
  --accent-gold: oklch(78% 0.12 85);
  --transition-ease: all 0.45s cubic-bezier(0.16, 1, 0.3, 1);
}
```

使用规则：

- 页面底色优先使用 `--bg-paper`。
- 面板、卡片、弹层优先使用 `--bg-surface`。
- 正文与标题默认使用 `--fg-ink` / `--fg-muted`。
- 强调仅使用 `--accent-cinnabar`，金色只作少量点染。

## 4. 字体与文本层级

- 标题、章名、纵向文字与东方语义组件优先使用衬线：`Songti SC / STSong / SimSun / Noto Serif CJK SC`
- 色值、技术文本、导出代码与参数优先使用等宽：`JetBrains Mono / SF Mono / ui-monospace`
- 常规交互与说明文本沿用系统无衬线

文本规则：

- 大标题允许更宽的字距与更松的行距。
- 次级说明保持克制，不堆砌修饰性文案。
- 中英文混排优先保证信息清晰，再考虑装饰性节奏。

## 5. 组件规范

### 5.1 通用卡片

- 默认复用 `spec-card`
- 1px 细墨灰边框
- 轻阴影，不使用厚描边和重玻璃态
- 常用圆角 16px，小组件 8-12px

### 5.2 朱砂印章

- 复用 `cinnabar-seal`
- 只用于关键动作、落款、局部标签
- 不做大面积重复装饰

### 5.3 纵向色柱 / 色签

- 复用 `color-rod`、`vertical-text` 及首页轮播的同类表达
- 适合承载主视觉、陈列、情绪化展示
- 不适合高密度操作区与复杂表单

## 6. 间距与边界

- 主区块上下间距：`32-64px`
- 卡片内边距：`20-24px`
- 边界默认使用 `1px` 细墨灰线
- 通过留白建立层级，优先减少噪音，而不是增加更多装饰线

## 7. 动效规范

- 默认使用缓入缓出
- 常规交互周期约 `450ms`
- 重点转场可延长到 `760ms`
- 优先使用位移、透明度、轻微缩放
- 避免旋转、剧烈弹簧、频闪和高频抖动

## 8. 移动端规范

- 详情与扩展操作统一使用 Bottom Sheet
- 小屏优先单列滚动，不强行维持桌面端并列结构
- 保证复制、选择、切换等核心动作有清晰触达路径

## 9. UI 改动约束

在进行任何 UI 调整时，优先按以下顺序决策：

1. 先复用现有 token、类名和组件基元。
2. 再通过间距、比例、位置和层级做细调。
3. 最后才考虑新增视觉样式或新的组件抽象。

不建议的改动：

- 为单一页面引入新的主色体系
- 在局部使用与全站风格不一致的重渐变、重阴影、重拟物
- 用过强动画替代清晰层级
- 用临时 class 覆盖现有设计 token，造成页面间风格漂移
